## Why core-llm / core-stt aren't finished

Two reasons, both explained in more detail inline where they matter:
1. **No native toolchain in my environment.** I can write CMake/JNI C++ that
   *should* be correct, but "should" isn't "verified" for native code the
   way it more often is for Kotlin/UI.
2. **I didn't trust the prebuilt AAR options I found.** When I searched for
   a maintained llama.cpp Android AAR, the top result was a package from an
   unverified single maintainer with a paid tier gating basic features —
   exactly the kind of native binary blob your original spec said to check
   with you before adding. So instead of vendoring that, both modules expect
   you to add the real upstream repos as git submodules:
   ```bash
   cd core-llm/src/main/cpp && git submodule add https://github.com/ggerganov/llama.cpp llama.cpp
   cd ../../../../core-stt/src/main/cpp && git submodule add https://github.com/ggerganov/whisper.cpp whisper.cpp
   git submodule update --init --recursive
   ```

## Getting it building — expected first-run errors

1. Open in Android Studio (Ladybird/Koala or newer), let Gradle sync.
2. Add the two submodules above.
3. Build. I'd genuinely expect the first build to fail in `llama_jni.cpp` /
   `whisper_jni.cpp` — the exact function names/signatures in `llama.h` and
   `whisper.h` drift between commits, and I wrote those two files from
   memory of the API shape, not from the checked-out header. **Paste me the
   real compiler errors** and I'll fix them against the actual headers
   rather than guessing again.
4. Everything outside those two `.cpp` files (all of `app`, `core-tools`,
   `core-tts`, `data`, and the Kotlin sides of `core-llm`/`core-stt`) should
   need little to no correction — that's ordinary Kotlin/Gradle/Compose,
   which I'm on much firmer ground writing correctly without compiling it.

## Filling in real model URLs/checksums

`data/src/main/java/com/bkpit/mangal/data/download/ModelCatalog.kt` has
placeholder `REPLACE_ME` URLs and `REPLACE_WITH_REAL_SHA256` checksums.
`ModelDownloadWorker` deliberately **fails loudly** rather than silently
"passing" verification if you forget to fill these in — that's intentional,
not a bug.
